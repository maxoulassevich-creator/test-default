# Instant Skeleton UX 2.1.0

Плагин создаёт skeleton не по универсальному шаблону, а по фактическому DOM-макету открываемой страницы.

## Главное изменение версии 2.0

Версия 1.x рисовала условные макеты: шапку, боковую колонку, карточки и другие заранее заданные блоки. Это не могло совпадать с конкретной страницей.

Версия 2.0 работает иначе:

1. Браузер строит реальный DOM и применяет CSS темы.
2. До первого точного снимка `body` скрыт через `opacity`, поэтому реальный контент не успевает мелькнуть.
3. JavaScript измеряет фактические координаты видимых строк текста, изображений, кнопок, полей, SVG, видео и iframe.
4. Поверх каждого элемента создаётся отдельная fixed-заглушка с теми же координатами, шириной, высотой и скруглением.
5. Фоны секций, `background-image`, градиенты, Elementor overlays, CSS-псевдоэлементы и декоративные слои не перекрываются общим полотном.
6. Исходный DOM не заменяется и не перестраивается. После завершения загрузки удаляется только отдельный слой заглушек.

Поэтому макет не меняется из skeleton в страницу: пользователь всё время видит одну и ту же реальную геометрию.

## Минимальное время показа

Поле **«Минимальное время показа, мс»** задаёт обязательную продолжительность skeleton.

Например, при значении `3000`:

- если страница готова через 400 мс, skeleton останется ещё до достижения 3000 мс;
- если страница готова через 4500 мс, skeleton исчезнет после готовности страницы;
- аварийный предел всё равно защищает от бесконечной загрузки.

Минимальное время отсчитывается от момента построения и показа точного skeleton, а не от начала PHP-запроса.

## Что именно распознаётся

Автоматически создаются заглушки для:

- каждой видимой строки текста через `Range.getClientRects()`;
- изображений;
- видео, canvas, iframe, object и embed;
- input, select, textarea и button;
- элементов с `role="button"` и `role="progressbar"`;
- стандартных кнопок WordPress, Elementor и WooCommerce;
- SVG-иконок, если они не помечены как декоративные;
- небольших пустых элементов с `background-image`, когда они выглядят как контент, а не как фон секции.

## Фон и декоративные элементы

Плагин не создаёт непрозрачный общий фон поверх страницы. Слой skeleton прозрачен, а заглушки находятся только там, где расположен реальный контент.

По умолчанию сохраняются:

- фактический цвет каждой секции;
- фоновые изображения;
- CSS-градиенты;
- `::before` и `::after`;
- Elementor background overlay и shape divider;
- WordPress Cover background;
- элементы с `aria-hidden="true"` или `role="presentation"`;
- характерные классы `decor`, `background`, `overlay`, `shape`, `pattern`, `blob`;
- крупные абсолютно позиционированные hero/banner-изображения с декоративными классами.

Для безусловного сохранения элемента добавьте:

```html
<div data-isux-preserve>...</div>
```

## Принудительная разметка

Можно вручную указать тип заглушки:

```html
<div data-isux-skeleton="box">...</div>
<span data-isux-skeleton="text">...</span>
<div data-isux-skeleton="circle">...</div>
```

Поддерживаются дополнительные CSS-селекторы в настройках плагина.

## Локальный светлый и тёмный режим

Цвет определяется не один раз для всей страницы, а отдельно для каждой заглушки.

Алгоритм ищет ближайший непрозрачный фон элемента. Если фон прозрачен или содержит изображение, дополнительно анализируется вычисленный цвет текста. Поэтому на одной странице skeleton может быть тёмным в светлой секции и светлым в тёмной секции.

При необходимости можно принудительно выбрать светлый или тёмный режим.

## Защита от скачков макета

Плагин не подменяет настоящие блоки фиктивной сеткой и не удаляет их из потока документа. Поэтому сам плагин не создаёт CLS при скрытии skeleton.

Опция стабилизации временно задаёт уже измеренную минимальную высоту для видимых изображений, видео и iframe. После скрытия skeleton временные свойства удаляются.

### Ограничение

Если у изображения до загрузки отсутствуют:

- атрибуты `width` и `height`;
- CSS `aspect-ratio`;
- заранее заданная высота контейнера;

браузер не знает будущую высоту изображения. Плагин не может точно восстановить неизвестное соотношение сторон. Для полной защиты от CLS размеры медиа должны быть заданы в теме или разметке.

## Автоматическое обновление снимка

Пока skeleton открыт, плагин отслеживает:

- изменение размеров страницы через `ResizeObserver`;
- добавление и изменение элементов через `MutationObserver`;
- загрузку изображений, видео и iframe;
- изменение размера окна;
- загрузку веб-шрифтов;
- прокрутку, если она не заблокирована.

Снимок перестраивается с ограничением частоты, чтобы не перегружать браузер.

## Навигация

### Обычная навигация

Перед переходом показывается точный снимок текущей страницы. После загрузки нового URL версия 2.0 строит уже точный skeleton новой страницы.

### AJAX-навигация

Дополнительный режим загружает HTML через `fetch(..., { cache: "no-store" })`, заменяет основной контейнер, после чего перестраивает skeleton по новой разметке.

По умолчанию AJAX отключён, поскольку сторонние виджеты могут требовать индивидуальной повторной инициализации.

## Исключения по умолчанию

Не обрабатываются:

```text
/wp-admin/
/wp-login.php
/wp-json/
/cart/
/checkout/
/my-account/
/order-pay/
/order-received/
?add-to-cart=
```

Для отдельной ссылки:

```html
<a href="/checkout/" data-isux-no-nav>Оформить заказ</a>
```

## JavaScript API

```js
window.InstantSkeletonUX.show('manual');
window.InstantSkeletonUX.rebuild();
window.InstantSkeletonUX.hide('manual');
window.InstantSkeletonUX.getState();
```

События:

```text
isux:show
isux:mirror:built
isux:hide
isux:navigation:before
isux:navigation:start
isux:content:ready
isux:navigation:complete
isux:navigation:error
```

## Установка обновления

1. Создайте резервную копию сайта.
2. Удалите старую версию плагина через раздел плагинов. Настройки WordPress сохранятся, если не запускать отдельное удаление данных.
3. Загрузите ZIP версии 2.1.0.
4. Активируйте плагин.
5. Откройте **Настройки → Skeleton UX**.
6. Сохраните настройки, чтобы новые параметры записались в базу.
7. Откройте точный предпросмотр.
8. Сначала используйте обычную навигацию. AJAX включайте после проверки на тестовой копии.

## Проверки сборки

Для версии 2.1.0 выполнены:

- синтаксическая проверка всех PHP-файлов;
- синтаксическая проверка frontend и admin JavaScript;
- проверка структуры ZIP;
- проверка наличия обязательного аварийного снятия `isux-booting`;
- проверка настроек обязательной минимальной продолжительности;
- проверка обработчиков фоновых, декоративных и принудительных элементов.

Полную совместимость с конкретной темой и всеми установленными на сайте плагинами можно подтвердить только после проверки на тестовой копии WordPress.
