1. Установите плагин

  1. В WordPress откройте Плагины → Добавить плагин → Загрузить плагин.
  2. Выберите архив woo-product-3d-viewer-1.4.1.zip. Распаковывать архив перед загрузкой не нужно.
  3. Нажмите Установить, затем Активировать. WooCommerce должен быть активирован.

Для доступа к инструкции после установки: Плагины → Woo Product 3D Viewer → Инструкция.

Обновление с 1.0.x / 1.1.x: загрузите новый ZIP через «Плагины → Добавить → Загрузить плагин» и нажмите «Заменить текущий плагин загруженным». После обновления активируйте плагин, если WordPress его деактивировал, и очистите кэш сайта, если он включён. Привязки моделей остаются в метаданных товаров: прежняя модель становится «Моделью 1». Управление кэшем переехало в WooCommerce → 3D-просмотр → Кэш моделей. При обновлении с 1.2.0 выключенная палитра остаётся выключенной: настройка «Показывать палитру цветов» превращается в два новых пункта с тем же значением.

2. Добавьте модель к товару

  1. Откройте Товары → Все товары → Изменить или создайте новый товар.
  2. В блоке Данные товара откройте вкладку 3D-модель.
  3. В блоке Модель 1 (открывается первой) нажмите Выбрать / загрузить модель. Загрузите GLB, FBX или OBJ либо выберите ранее загруженный файл из медиатеки.
  4. Если нужно показать товар в разных видах (в сборе и в разобранном виде, в разных цветах, с упаковкой), заполните Модель 2 и Модель 3. Они необязательны.
  5. В поле Название на переключателе напишите короткую подпись, например «В сборе», «Красный», «Упаковка» (до 40 символов). Без подписи покупатель увидит «Модель 1», «Модель 2»…
  6. Нажмите Предпросмотр, чтобы проверить выбранный файл до сохранения товара.
  7. Настройте автовращение, скорость, начальное направление и фон. Поле «Цвет без материалов» задаёт цвет OBJ и сеток FBX, у которых нет материала.
  8. Нажмите Обновить или Опубликовать.

Для первой проверки можно загрузить examples/demo-chair.glb или examples/demo-chair.fbx из архива. Это демонстрационная модель кресла. Она не привязывается к товарам автоматически.

У каждой модели может быть своя облегчённая версия для телефонов. Автовращение, скорость, поворот, цвет и фон общие для всех моделей товара.

Кнопка Убрать снимает привязку файла к товару. Сам файл сохраняется в медиатеке; другие товары с этим файлом не затрагиваются.

3. Разместите кнопку

Добавьте этот шорткод там, где нужна кнопка:

[product_3d_button]

На странице товара он использует текущий товар WooCommerce. В Elementor / Elementor Pro добавьте виджет Шорткод в шаблон страницы товара и вставьте указанную строку. Обновите шаблон.

Для конкретного товара, например на обычной странице:

[product_3d_button id="123" label="Посмотреть товар в 3D"]

Замените 123 на ID товара. Дополнительный CSS-класс:

[product_3d_button class="my-product-3d-button"]

Другой вариант — включить Автоматическая кнопка во вкладке товара. Она выводится после стандартного блока покупки WooCommerce через woocommerce_single_product_summary, приоритет 35. Если ваш шаблон этот хук не вызывает, разместите шорткод вручную. Выберите один способ размещения, чтобы не получить две кнопки.

В редакторе блоков WordPress используется блок Шорткод. Отдельный блок плагин не добавляет. Предпросмотр Elementor без выбранного тестового товара может не показать кнопку: проверьте опубликованную карточку или задайте ID явно.

Несколько моделей: переключатель в окне

Если у товара сохранено две или три модели, в окне просмотра появляется панель с их названиями. Окно открывается с моделью 1; выбранная модель выделена цветом, а над названием товара видно «1/3», «2/3»…

  • Телефон и планшет: панель находится внизу области модели, под большим пальцем. Каждая кнопка не меньше 44×44 px, кнопки делят ширину поровну; длинное название сокращается многоточием, полное видно во всплывающей подсказке.
  • Компьютер: щелчок по названию. С клавиатуры: Tab до панели, стрелки ←/→, Home/End выбирают кнопку, Enter или пробел открывает модель. Цифры 1–3 переключают модели из любого места окна.
  • Фон и цвет модели, выбранные в палитре, сохраняются при переключении. Камера для каждой модели выставляется заново по её размеру.
  • Модель загружается при выборе, а не все сразу. Быстрое переключение отменяет загрузку предыдущей модели, на экране остаётся последняя выбранная.
  • Если файл одной из моделей перестал проходить проверку, она не показывается на переключателе; остальные работают. Если подходит только одна модель, панели нет.

Расположение панели (внизу или вверху области модели) и её цвета настраиваются на странице WooCommerce → 3D-просмотр.

Внешний вид кнопки и окна

Откройте WooCommerce → 3D-просмотр → Внешний вид (или ссылку Настройки в списке плагинов). Страница доступна администратору и менеджеру магазина. Настройки действуют для всех товаров и шорткодов.

4. Модели для вариаций

Для вариативного товара откройте Данные товара → Вариации, раскройте вариант и выберите его 3D-файл. Нажмите Сохранить изменения в вариациях.

  • После выбора варианта покупателем кнопка переключается на модель этого варианта.
  • У вариации одна модель (и необязательная облегчённая). Если своего файла нет, показываются все модели основного товара вместе с переключателем.
  • Если модели есть только у вариаций, до выбора подходящего варианта кнопка неактивна.
  • Шорткод с ID конкретной вариации показывает именно её модель и не переключается при выборе другого варианта.
  • Изображения, цена и покупка WooCommerce работают независимо от окна 3D.

Переключение рассчитано на стандартную форму вариаций WooCommerce. Нестандартная форма, которая не отправляет событие found_variation, потребует отдельного подключения.

Палитра фона и модели

В окне просмотра нажмите Палитра. Выберите вкладку Фон или Модель, затем нажмите на образец цвета. Для другого оттенка нажмите квадрат рядом с надписью Свой цвет — откроется цветовая палитра браузера.

  • Исходный фон возвращает фон, заданный в товаре.
  • Исходные цвета возвращает оригинальные материалы и цветные текстуры модели.
  • На узком или низком экране палитра закрывается после выбора образца, чтобы показать результат на модели. Для другого цвета снова нажмите «Палитра».
  • Цвета обновляются сразу. Перекраска меняет базовый цвет поверхностей всей модели; альфа-канал текстур, рельеф, матовость, металл и свойства свечения сохраняются.
  • Эти цвета служат для просмотра. Они не сохраняются в товаре или в заказе и не переключают вариации. При новом открытии окна модель снова имеет исходные цвета.
  • «Сбросить вид» сбрасывает положение камеры; возврат цвета выполняется кнопками в палитре.
  • Палитру можно ограничить или отключить на странице WooCommerce → 3D-просмотр → Внешний вид → Палитра и значок 360°: «Палитра: смена фона» и «Палитра: перекраска модели» включаются отдельно. Без перекраски модель всегда показывается с материалами, текстурами и цветами из файла (OBJ и сетки FBX без материала — цветом «Цвет без материалов» из товара); без смены фона фон всегда такой, как задан в товаре. Если разрешён один пункт, в палитре нет вкладок, только заголовок «Цвет фона» или «Цвет модели». Если выключить оба, кнопки «Палитра» в окне нет.
  • Escape закрывает сначала открытую палитру, затем окно просмотра. Между вкладками палитры можно переходить стрелками влево и вправо.

Кэш, скорость и Safari на iPhone

Кэш включён автоматически. На сайте создаются проверенные копии файлов в wp-content/uploads/w3dpv-model-cache/. Их имена зависят от содержимого модели и поколения кэша. Максимальный объём копий — 512 МиБ; при заполнении удаляются самые старые. Создание копий за один запрос ограничено 120 МиБ, чтобы страница с множеством вариаций не копировала сразу все модели.

Через WP-Cron копии очищаются каждые 30 дней. Исходные модели и настройки товаров остаются. Копии создаются снова по мере обращения к страницам товаров. Управление: WooCommerce → 3D-просмотр → Кэш моделей; там видны объём кэша, время следующей задачи и кнопка ручной очистки. WP-Cron зависит от посещений. Если он отключён, хостинг должен запускать wp-cron.php системным cron.

В браузере проверенный файл сохраняется через IndexedDB до 30 дней при наличии HTTPS и доступного хранилища. При открытии из этого кэша модель не скачивается заново, но браузер заново подготавливает геометрию, материалы и графику. Лимит браузерного кэша: до 240 МиБ на компьютере, до 120 МиБ на сенсорном устройстве, не более 8 записей. Маленькая модель дополнительно повторно используется в памяти текущей страницы (до 16 / 8 МиБ). Истёкшая запись не используется; при сохранении нового файла старые записи очищаются. Браузер также может сам удалить данные при нехватке места. Отказ хранилища не блокирует просмотр.

Очистка на сайте меняет поколение кэша для новых страниц. После ручной очистки или замены модели очистите кэш страниц сайта и CDN, чтобы раздать актуальные адреса. Если посетитель открывает старую страницу сразу после очистки, плагин может взять файл с исходного адреса, без ошибки 404 в просмотре.

При наведении или фокусе на кнопке на компьютере плагин заранее загружает модуль просмотра и одну модель. Загрузка модели пропускается на сенсорном устройстве, при режиме экономии трафика и при известном медленном 2G-соединении. На нажатие модуль и файл загружаются параллельно. Скачивание прекращается после закрытия, если файл не нужен другой активной предварительной загрузке.

Первый просмотр: кэш содержит тот же файл, а не автоматически уменьшенную модель. Первая загрузка 33 МиБ зависит от сети, сервера, сложности геометрии и текстур. Для быстрого первого просмотра подготовьте GLB до 5–10 МиБ, уменьшите сетку и текстуры в 3D-редакторе. Автоматическое создание LOD/сжатие исходного GLB на хостинге плагин не выполняет.

Облегчённая модель. В товаре и каждой вариации есть отдельное необязательное поле «Облегчённая модель для телефонов». Загрузите в него подготовленный GLB/FBX/OBJ; на iPhone, iPad и небольших сенсорных экранах плагин выберет его автоматически. Без него используется основной файл. Для вариации со своим основным файлом нужна своя облегчённая модель, иначе на телефоне показывается её основной файл. Это предотвращает подмену модели другой вариацией.

Чёткость на телефонах и планшетах. Модель рисуется с удвоенной плотностью пикселей (как у экрана Retina) и со сглаживанием краёв, но не больше 2,4 млн пикселей холста; на компьютере — до 5 млн. Для файлов больше 40 МиБ на телефоне сглаживание (MSAA) отключается, чтобы сэкономить память, а удвоенная плотность остаётся. Если браузер всё-таки сбросил графику (сообщение «Графический контекст прерван»), кнопка «Попробовать снова» открывает модель в лёгком режиме: обычная плотность пикселей без сглаживания.

Режим для iPhone. Просмотр использует освещение с меньшим расходом памяти, один поток декодирования и обычный загрузчик изображений в локальном GLTFLoader. Обычные PNG/JPEG/WebP текстуры перед отправкой на GPU уменьшаются до 2048 px по длинной стороне; исходный GLB на сервере не изменяется. Текстуры KTX2 так не преобразуются — их размер должен соответствовать устройству. Даже после уменьшения картинок браузеру сначала нужно декодировать встроенные изображения; очень тяжёлая модель может требовать отдельной облегчённой версии.

Для просмотра нужен WebGL 2. При ошибке окно показывает понятное сообщение и код DOWNLOAD, WEBGL2, DECODE, RENDER, CONTEXT_LOST, TIMEOUT или VIEWER_MODULE. Кнопка «Попробовать снова» заново читает исходный файл. Авторизованный редактор товара видит кнопку копирования диагностики при ошибке. Диагностика содержит версию, браузер, размер модели и этап; данные не отправляются разработчику или во внешние сервисы автоматически.

Проверено в Chromium и Linux WebKit с мобильным размером экрана и user-agent iPhone; это не испытание физического iPhone. Если Safari на конкретном устройстве всё ещё не открывает модель, нужны сам GLB, ссылка на товар, версия iOS и текст ошибки/диагностика. Одного размера файла недостаточно для определения причины.

HTTP-кэш на сервере. Для Apache в папке копий создаётся отдельный .htaccess с MIME и Cache-Control: public, max-age=2592000, immutable. На Nginx правила .htaccess не применяются: при необходимости хостинг настраивает такие заголовки для этой папки. Кэш браузера через IndexedDB работает независимо от этих заголовков; заголовки CDN нужно проверить на самом сайте.

6. Подготовьте файл модели

ФорматПоддержка
GLB 2.0Геометрия и встроенные материалы/текстуры. В сборку включены загрузчики Draco, Meshopt и KTX2. Внешние ссылки на текстуры, BIN-файлы и другие ресурсы запрещены.
FBX 7.xFBX 2011 и новее (версии 7000–7700), двоичный или ASCII. Загружаются сетки, материалы Phong/Lambert (переводятся в PBR с сохранением цвета, текстуры, прозрачности, рельефа и свечения) и встроенные текстуры PNG, JPEG, TGA, BMP, WebP. Внешние файлы текстур не запрашиваются: такие поверхности показываются цветом материала. Z-up сцены (3ds Max) поворачиваются автоматически. Источники света, камеры и кривые из файла не используются; анимация и скелет остаются в исходной позе. Старые FBX 6.x (2006–2010) не поддерживаются.
OBJПолигональная геометрия. Внешний MTL-файл и отдельные текстуры не загружаются. Применяется цвет из настроек товара; встроенные цвета вершин, если они есть, сохраняются.

Нужны исходные цвета и текстуры? Экспортируйте модель в GLB со встроенными ресурсами или в FBX с включённым Embed Media (Blender: Path Mode → Copy и значок «Embed Textures»; 3ds Max/Maya: Embed Media). Одного OBJ-файла недостаточно для передачи внешних материалов и текстур. GLB остаётся лучшим форматом для сайта: он меньше, быстрее открывается и точнее передаёт PBR-материалы. FBX разбирается в браузере дольше и требует больше памяти.

При экспорте из Blender выберите glTF 2.0 → glTF Binary (.glb), включите необходимые объекты и материалы. Проверьте ориентацию товара. Начальный поворот вокруг вертикальной оси можно изменить в настройках товара; остальные преобразования лучше исправлять в 3D-редакторе.

  • Максимальный размер файла — 120 МиБ. Лимит загрузки хостинга может быть меньше: он виден в «Медиафайлы → Добавить» («Максимальный размер файла»). Для файлов до 120 МиБ в PHP нужны upload_max_filesize и post_max_size не меньше 128M — их меняет хостинг или администратор сервера.
  • Проверка загрузки считает то же, что потом строит просмотр, поэтому принятый файл не отклоняется при открытии. Лимиты: до 2 000 000 вершин в файле и не больше 2000 отдельных сеток в сцене. Для FBX — до 3 000 000 треугольников после разбиения четырёхугольников и многоугольников (с учётом повторяющихся копий одной геометрии) и до 512 МиБ распакованных массивов; для GLB — до 6 000 000 вершин в сцене с учётом копий и до 256 МиБ геометрии и встроенных текстур; для OBJ — до 2 000 000 треугольников. Если файл превышает лимит, сообщение называет фактические числа и подсказывает, что сделать. Что такое вершины и как их уменьшить в Cinema 4D — в разделе «Подготовка модели в Blender».
  • Верхние лимиты рассчитаны на компьютер. FBX на 3 000 000 треугольников требует при открытии около 2 ГБ памяти браузера, поэтому для телефонов загрузите в товар облегчённую модель: телефон с такой моделью может закрыть вкладку.
  • Проверка при просмотре дополнительно отклоняет текстуры больше 8192 пикселей по стороне (на телефоне — больше возможностей устройства).
  • Практический ориентир для мобильного просмотра: файл до 5–10 МиБ, сетка до 100–200 тысяч треугольников, текстуры до 2048 пикселей. Это рекомендация для подготовки, а не гарантия скорости на каждом устройстве.
  • Встроенные клипы анимации GLB и FBX не проигрываются. Плагин вращает камеру вокруг формы товара.
  • Модель доступна в браузере и может быть сохранена посетителем. Плагин не предназначен для защиты 3D-файла от скачивания.

Подготовка модели в Blender: инструкция для дизайнера

Лучше всего экспортировать модель в GLB (glTF Binary): это один файл, в котором уже лежат геометрия, материалы и текстуры. Подходит и FBX, но материалы в нём переносятся проще и хуже. Названия команд даны как в английском интерфейсе Blender 4.x. Эта же инструкция отдельной страницей для пересылки дизайнеру — файл blender-guide-ru.html рядом с архивом плагина.

Что такое «вершины» в сообщении плагина

  • Вершина — точка сетки, угол полигона. Blender показывает их как Vertices; вершины в сообщении плагина — это они же, но в уже экспортированном файле.
  • При экспорте одна вершина Blender часто превращается в несколько: на швах UV-развёртки, на острых рёбрах (Sharp, Auto Smooth) и на границе двух материалов. Поэтому в файле вершин обычно в 1,5–3 раза больше, чем показывает Blender.
  • Как посмотреть: в правом верхнем углу окна 3D-вида откройте меню Viewport Overlays и включите Statistics — в левом верхнем углу появятся Objects, Vertices, Faces и Triangles. Смотрите в Object Mode: там считается вся видимая сцена вместе с модификаторами.
Где смотрят модельОриентир в Blender (Statistics)
Компьютер (лимит плагина)До ~700 000 вершин — тогда в GLB почти всегда меньше 2 000 000. Для FBX — до 3 000 000 треугольников.
Телефон (поле «Облегчённая модель для телефонов»)100–200 тыс. треугольников, текстуры до 2048 px, файл до 5–10 МиБ.

Как уменьшить число полигонов

  1. Subdivision Surface: каждый уровень умножает число полигонов в 4 раза. Поставьте Levels Viewport и Render одинаково — 1 или 2.
  2. Модификатор Decimate: режим Collapse, начните с Ratio 0,5 и уменьшайте, пока не начнёт портиться силуэт. Для листового металла и плоских деталей хорошо работает режим Planar: он убирает лишние рёбра на плоскостях и не трогает форму.
  3. Bevel: Segments 1–3, Limit Method — Angle. Фаска в 5 сегментов на каждом ребре — частая причина миллионов полигонов.
  4. Array и копии: каждая копия — отдельная геометрия. Уменьшите число копий или упростите копируемый объект.
  5. Перфорация, насечки, гравировка, логотипы через Boolean или скульптинг дают сотни тысяч полигонов. Для сайта их лучше нарисовать текстурой: рисунок — в Base Color, рельеф — в Normal, сквозные отверстия — в Alpha.
  6. Чистка в Edit Mode: Mesh → Clean Up → Merge by Distance и Delete Loose. Удалите то, чего не видно: внутренние винты, задние стенки, скрытые объекты.
  7. Если отдельных объектов больше 2000: выделите детали с одним материалом и нажмите Ctrl+J.

Чтобы текстуры и материалы показались правильно

  1. Шейдер — только Principled BSDF, подключённый к Material Output. Diffuse BSDF, Glossy BSDF, Mix Shader и шейдеры аддонов не переносятся.
  2. Что переносится в GLB: Base Color (цвет или картинка), Metallic (металл — 1, краска и пластик — 0), Roughness (0 — зеркало, 1 — мат), Normal через узел Normal Map, Alpha (прозрачность), Emission (свечение). Если Metallic и Roughness не подключены, переносятся значения ползунков. Если они идут из одной картинки, по стандарту glTF шероховатость лежит в зелёном канале, а металличность — в синем; разведите их узлом Separate Color.
  3. Картинки подключайте прямо ко входам Principled BSDF через узел Image Texture (узел Mapping допускается). Процедурные текстуры (Noise, Voronoi, Wave, Brick, Gradient), Color Ramp, Mix, Math, Bump, Layer Weight, Fresnel и свои группы узлов не экспортируются — их результат нужно запечь.
  4. Запекание: Render Properties → Render Engine → Cycles; в материал добавьте узел Image Texture с новой картинкой 2048×2048 (для крупного товара — 4096; для нормалей — Color Space Non-Color), не подключайте его, но оставьте выделенным; в Render Properties → Bake выберите Diffuse с выключенными Direct и Indirect (для цвета), затем Roughness и Normal — для каждой карты своя картинка; нажмите Bake и сохраните результат (Image → Save As). Затем соберите простой материал: Image Texture → Base Color, → Roughness, → Normal Map → Normal.
  5. UV-развёртка: glTF понимает только UV-координаты. Если текстура положена по координатам Generated, Object или Box, разверните объект (в Edit Mode — U → Smart UV Project или вручную).
  6. Картинки: JPEG для цвета, PNG — если нужна прозрачность; 2048 px — для телефона, до 4096 px — для компьютера.
  7. Нормали: включите Viewport Overlays → Face Orientation. Красные грани смотрят внутрь — выделите их и нажмите Shift+N, иначе на сайте они могут пропасть.

Нержавейка и другой металл. Полированная нержавейка: Base Color около #C0C4C8, Metallic 1, Roughness 0,15–0,25; шлифованная — Roughness 0,4–0,55; чёрный металл с порошковой краской — #2A2C2E, Metallic 0, Roughness 0,45–0,7. Металл на сайте отражает студийное освещение просмотрщика, поэтому без текстур он выглядит ровным серебристым — это нормально. Надписи, логотипы и шлифовка видны, только если они есть в текстуре или в геометрии.

Если модель сделана в Cinema 4D

Правила те же, отличаются названия: число точек и полигонов — Shift+V → HUD → Total Points / Total Polygons; упрощение — генератор Polygon Reduction и меньший уровень Subdivision Surface; объединение деталей — Connect Objects + Delete. Материал — только стандартный (Standard Material): Node-материалы, Redshift, Octane, Corona, V-Ray и Arnold в glTF не экспортируются, процедурные шейдеры запекаются тегом Bake Texture, проекция текстур — только UVW (Generate UVW Coordinates). Экспорт: File → Export → glTF (*.glb); для FBX — включить Textures and Materials и Embed Textures.

Источники: руководство Blender glTF 2.0 и Viewport Overlays; справка Maxon glTF Export Settings и FBX Export Settings. В разных версиях программ названия пунктов могут немного отличаться.

7. Требования и границы совместимости

Минимальные заявленные требования к плагину: WordPress 6.5, PHP 7.4, WooCommerce 8.0. Интерфейс настроек рассчитан на классическую страницу редактирования товара WooCommerce с блоком «Данные товара». Отдельная интеграция с экспериментальным редактором товаров не реализована.

Для просмотра нужен современный браузер с WebGL 2 и JavaScript. При недоступном графическом контексте окно показывает сообщение. Реальные проверки и их ограничения описаны в TEST-REPORT.txt; заявленные минимальные версии не означают, что каждая промежуточная версия и каждая тема проверены.

Файлы модели должны оставаться на сервере в стандартной папке загрузок WordPress. Хранение только во внешнем облаке с удалением локальной копии не поддерживается. На компьютере предварительная загрузка начинается при наведении или фокусе на кнопке; при открытии модуль и модель загружаются параллельно; файлы библиотек и декодеров находятся внутри плагина. При закрытии окно освобождает созданные графические ресурсы. GLB проверяется на ограничения формата, но это не полная сертификация по всей спецификации glTF.

При деактивации или удалении плагина привязки в метаданных товара и файлы медиатеки сохраняются. При удалении плагина через «Плагины → Удалить» стираются его настройки внешнего вида и кэша, служебные метаданные проверки файлов и папка копий w3dpv-model-cache (если в ней нет посторонних файлов). Если их нужно удалить окончательно, удаляйте модели через медиатеку после проверки, какие товары их используют.

OBJ использует выбранный цвет. FBX показывает только встроенные текстуры: экспортируйте его заново с Embed Textures / Embed Media или загрузите GLB со встроенными изображениями. 9. Для разработчика

Метаданные товара: _w3dpv_model_id, _w3dpv_mobile_model_id, _w3dpv_model_label (модель 1), _w3dpv_model_2_id, _w3dpv_mobile_model_2_id, _w3dpv_model_2_label, _w3dpv_model_3_id, _w3dpv_mobile_model_3_id, _w3dpv_model_3_label, _w3dpv_auto, _w3dpv_speed, _w3dpv_yaw, _w3dpv_color, _w3dpv_background, _w3dpv_show_button. У вариаций сохраняются отдельные _w3dpv_model_id и _w3dpv_mobile_model_id; настройки отображения наследуются от основного товара.

Исходный просмотрщик находится в source/viewer.js. Для пересборки используйте Node.js 22+, в папке source выполните npm install, затем npm run build. При обычной установке в WordPress Node.js не требуется.

Настройки внешнего вида хранятся в опции w3dpv_style и выводятся как CSS-переменные --w3dpv-btn-bg, --w3dpv-dlg-bg, --w3dpv-ctl-bg, --w3dpv-sw-active-bg и другие (полный список — в includes/class-w3dpv-settings.php). Их можно переопределить в CSS темы.

Атрибут data-w3dpv кнопки содержит {"models": [{"model": …, "mobileModel": …, "label": "…"}], "model": …, "mobileModel": …, …}; поля model/mobileModel повторяют первую модель для совместимости с разметкой 1.1. Доступен API window.W3DPV.open(settings, trigger, index) / window.W3DPV.select(index) / window.W3DPV.close() / window.W3DPV.diagnostics() после загрузки скрипта. События w3dpv:open (detail: index, count), w3dpv:model (переключение модели) и w3dpv:close отправляются на document. Это события интерфейса; никаких запросов в системы аналитики плагин не отправляет.

Проверка capability и nonce защищает сохранение настроек. MIME-тип разрешается только после проверки содержимого файла. Чтение модели выполняется с публичного URL вложения; публичный JSON/AJAX-метод выдачи произвольных товаров плагин не добавляет.
